# 全游戏前情提要 · 千里寻兄

更新于 2026-11-22。用户已确认动态连环画、45–55 秒、清楚易懂且兼顾情感的方向，并指定本版使用 ElevenLabs 中文老先生说书配音。本文按六幕、标准自动播放约 51 秒设计，末幕可停留阅读。六幕动画、中文旁白与 Godot 接入已实现，字幕仍为项目改编稿，待正式文本审定与真人理解测试。

本片为整个游戏的开篇，文件名保留原有路径。[五关旅图与前情回顾](five-passes-map-spec.md) 已接入：首次结束或主动跳过后到地图，以后直接到地图；地图回顾返回原选择，文化卡回顾返回原卡。六幕画面、配音、字幕与声音控制继续复用。

## 玩家需要理解的事

前情结束后，第一次接触故事的玩家应能说清以下关系和目的。

- 玩家扮演关羽。刘备是他的结义兄长。
- 徐州兵败后，二人失散。关羽肩负照顾刘备家眷的责任，暂留曹营。
- 关羽与曹操约定，一旦得知刘备下落，便辞别前往。
- 得知刘备在河北后，关羽护送刘备的甘夫人、糜夫人出发，目标是与刘备重逢。
- 旅途中要通过关隘。东岭关是本游戏的第一关，通关文书成为接下来的冲突起因。

叙事以护送与重逢贯穿各幕。“过五关斩六将”作为作品主题，由旅途中遇到的阻碍展开；前情先把人物的出发理由讲清。

## 画面与声音

采用游戏现有的山关色调、纸色字幕和墨绿界面。六幕使用完整像素连环画，每幅将人物、道具与环境一起绘制，统一透视、光照、比例与接触阴影。关羽保持红脸、长髯、绿袍和青龙偃月刀；甘夫人青衣，糜夫人紫衣，跨幕维持身份。图片使用最近邻采样。

每幕围绕一个叙事重点组织构图：战乱中的分离、门外守护、灯下读信、挂印辞行、回望车仗和关前受阻。用户反馈首版独立图标过于生硬后，改为整幅画面约 1.5% 的轻微推近；翻幕用约 0.45 秒的旧画面交叉淡出。人物、卷轴或印信不再单独滑动、展开或消失。动态来自镜头和转场，不宣称有独立人物动作帧。

字幕在 960×540 逻辑画布底部独立排版，建议正文 22–24 像素，最多三行。人物关系在顶部用短行说明，信纸和画中道具不承载生成文字，给字幕保留阅读空间。关键文字由 Godot Label 绘制，新增汉字需重建字体子集。

声音设计包括风声、纸张、印信轻响、车轮与远处关门声，控制转场时的音量连续性。本版交付六幕中文旁白，字幕与实际念出的正文对应，人物标签和播放按钮独立显示。开发预览可先验证字幕流程，配音版验收时核对全部六幕音频。前情右上角直接提供声音开关，字幕旁提供“重听本幕”，静音时显示“当前静音”。声音开关统一控制前情音频。

## ElevenLabs 中文说书配音

本版由同一位中文男声旁白贯穿六幕。声音具有约六十至七十岁老先生的阅历感，音色温厚、略带沙感，字头清楚，句尾收得稳。节奏有说书的轻重缓急，人物关系与地名保持容易听懂。关羽的承诺由说书人轻微转为坚定口吻代言，仍使用同一音色。

配音导演说明如下，作为选声与试音依据。

> 一位阅历深厚、温厚沉稳的中国老先生，用清楚自然的普通话讲述关公千里寻兄的故事。语速从容，断句分明，带轻微沙感和自然气息。说到兄弟失散时稍沉，得知刘备尚在时透出宽慰，挂印辞曹时坚定，护送二位夫人时有体恤，关门前收紧语气，留下故事将起的悬念。

说明文字用于声音选择、声音设计和模型支持的表演控制。合成请求的正文只放实际台词及经试音验证的控制标记，字幕只显示台词。由此保证导演说明、幕号和音频标记在成品中各司其职。

| 幕 | 表演与停顿 |
| --- | --- |
| 乱世失散 | 首句可试“话说，徐州兵败……”，声线低稳，在“失散”后稍停，让画面交代人物 |
| 暂留与约定 | 甘夫人、糜夫人分别念清；“一有兄长消息”略加重，听出约定 |
| 兄长尚在 | “尚在人世”稍见宽慰，“河北”清楚落音 |
| 挂印辞曹 | “封存赏赐、挂印留书”各有短停顿，辞别一句有决断 |
| 护送同行 | “二位嫂嫂放心”温和，后半句坚定，保留承诺的完整气口 |
| 东岭关前 | 在“仍须文书”后停一下，“东岭关”收束，留出关门画面的余韵 |

语气以自然说书和叙事清楚为审听标准。试音时检查沙哑程度、拖腔、儿化、笑声和情绪强度，选择最能听清人名与因果的一版。正式旁白目标时长仍在 45–55 秒内，镜头停留根据定稿录音微调。

当前配置的首选模型为 `eleven_v4`，输出格式为 `mp3_44100_128`。语言使用普通话中文，模型支持语言参数时明确指定 `zh`。每轮生成由助手查询当时可用的中文男声，按老先生的年龄感、说书节奏和人名发音选择音色，并核对其在本地 Key 对应账户中的可用性。用户负责填写 API Key，音色由助手选择并作为本次生成参数传入工具。

先用“挂印辞曹”和“护送同行”中的短句合成约 10–15 秒试音。助手审听后为该版六幕固定同一 voice ID、模型与主要生成设置，按六幕分别合成，逐幕检查“糜夫人”的“糜”、关羽、刘备、曹操、河北和东岭关的读音。补录某一幕时先核对该版已选声音，维持同一位说书人的听感。字幕里的“关羽”是说话人标签，合成该句时正文从“二位嫂嫂放心”开始。每幕保留实际音频时长，配合幕间停顿调整总时长。

Eleven v4 的暂停和情绪控制按该模型的官方规则处理。首轮优先用中文标点、自然分句与模型支持的音频标记调整节奏；审听确认标记只影响表演。正式生成前查询账户可用模型及所选声音，若配置不可用，给出具体原因，由配置选择可用模型和声音。

官方接口和模型依据见[语音合成入门](https://elevenlabs.io/docs/eleven-api/guides/cookbooks/text-to-speech)、[模型列表](https://elevenlabs.io/docs/overview/models)、[语音合成接口](https://elevenlabs.io/docs/api-reference/text-to-speech/convert)和[配音控制说明](https://elevenlabs.io/docs/overview/capabilities/text-to-speech/best-practices)。

## 本地凭据与生成文件

用户在仓库根目录的 [.env](../../.env) 填写 ElevenLabs 凭据。该文件与 `godot/` 同级，已加入 Git 忽略规则。仓库中同时提供 [.env.example](../../.env.example) 作为空值模板。用户填写 Key，模型保留默认值即可。

```dotenv
ELEVENLABS_API_KEY=
ELEVENLABS_MODEL_ID=eleven_v4
```

| 字段 | 用途 |
| --- | --- |
| `ELEVENLABS_API_KEY` | ElevenLabs 账户 API Key，由本地生成工具用于请求认证 |
| `ELEVENLABS_MODEL_ID` | 配音模型，模板预置 `eleven_v4` |

`tools/generate_prologue_voice.py` 已实现单段配音生成，从自身文件位置定位仓库根目录，以绝对路径读取 `.env`。Python 实现使用 `dotenv_values(env_path, interpolate=False)` 获取文件内配置，再将文件中的 Key 显式传给 `ElevenLabs(api_key=...)`。凭据来源固定为该文件，缺失文件或空 Key 时，在请求发出前给出字段级提示。助手完成声库查询、选声及可用性核对后，将 voice ID 作为此次调用的工具参数传入；工具将该选择写入生成记录，便于后续补录。工具依赖 `python-dotenv`、`elevenlabs` 与用于校验音频的 `ffprobe`，本机已具备。

Shell 中已经存在的 Key、全局环境变量及 Shell 配置文件均不参与凭据解析，也不执行 `source .env` 或 `export`。生成工具的日志只报告字段是否已配置、幕名、模型和生成结果，Key 始终保留在本地配置与 API 认证环节。

前情音频采用本地预生成流程。开发工具调用 ElevenLabs 后，将试听文件保存到已忽略的 `builds/audio/prologue/zh-CN/`，六幕使用 `01-separation.mp3` 至 `06-dongling.mp3` 等稳定文件名。修改台词时按幕重新生成，保留已通过审听的文件。生成记录保存模型、音色 ID、台词版本和实际时长。

选定成品后，音频复制到 `godot/assets/prologue/audio/zh-CN/`，并在素材来源文件中注明 ElevenLabs、声音和生成日期。游戏通过 `AudioStreamPlayer` 播放工程内音频，支持离线游玩。Key 和本地生成配置留在运行工程外，游戏导出流程只读取 `godot/` 中的成品资源。

首段约 12.72 秒试音已获用户认可，文件位于 `builds/audio/prologue/zh-CN/storyteller-sample-01.mp3`。正式六幕沿用 Mr. Chen 中文叙事音色与 `eleven_v4`，voice ID 为 `cwzmKSYMCC9Aym1ymCnt`，作为生成参数传入。六段音频已接入，实际时长分别为 5.06、8.32、4.48、8.16、4.40、8.08 秒；镜头含留白共 51 秒。首幕按用户反馈从原录音去掉重复的第一遍“话说”，保留第二遍与正文；第一幕仍停留 7 秒。音色、台词、剪辑记录及实际时长见 `godot/assets/prologue/voice-manifest.json`。

## 播放、跳过与重看

- 从主菜单“启程”进入六幕前情，首次进入可观看或跳过，之后直接进入旅图。失败重试和 Boss 检查点重试直接按现行玩法恢复。
- 默认自动播放。底部提供“上一幕”“暂停播放／自动播放”“继续”，右上角提供声音开关与“跳过前情”。首幕的“上一幕”置灰，末幕确认改为“展开旅图”（地图回顾为“返回旅图”）。
- “重听本幕”保留当前幕号，从本幕开头重新计时并播放，恢复自动模式和声音；静音时有明确提示。
- Web 使用 `godot/web/game.html` 检查 AudioContext 状态，用户点击或按键时尝试开启音频。上下文未运行且未静音时，时间轴和三个音频播放器先等待，显示原生网页“开启声音／静音观看”选择。只有音频准备好或用户明确选择静音才继续。
- 六段旁白预加载，AudioStreamPlayer 明确使用 Stream 播放方式；旁白增益为 +2 dB，环境与拟音保持较轻音量。已检查原 MP3 峰值，增益后仍有余量。Web 解锁按钮的短暂 DOM 焦点转移不触发游戏暂停，真实窗口失焦和隐藏标签页仍暂停。
- Enter 和“继续”进入下一幕，并从该幕起重新计时。先暂停后翻幕，后续仍保持手动阅读模式。上一幕进入该幕开头。
- Esc/P 进入游戏暂停界面。窗口失焦时，字幕时间、AnimationPlayer、独立 Tween 和音频同步暂停。恢复时从原进度继续。
- 整幅画面的空白点击用于维持阅读。翻幕与跳过均通过明确按钮或对应键盘操作完成。
- “跳过前情”停止前情的所有动画和声音，先进入旅图，明确开始关卡后才进入教程。教程起始目标同时显示“护送二位夫人，过关寻刘备”，保证跳过者仍能获得任务信息。
- 主菜单“故事与文化”内增加“重看前情”入口。重看结束或跳过后回到文化卡，沿用已有最佳成绩。重看末幕按钮为“返回”；地图回顾为“返回旅图”。
- 每次鼠标抬起或键盘按下最多推进一幕；翻幕后清除旧输入。末幕 Enter 和按钮触发统一进入完成函数，教程初始化仅执行一次。
- 进入教程前等待本次鼠标按键与确认键释放，再启用移动和战斗输入。玩家按住 Enter 或连续按“启程”时，能够稳定停在正确流程。

首次启程与文化卡重看使用明确的调用来源。重看直接展示前情，不调用新行程重置，不写通关或最佳成绩，也不改动临时检查点。返回菜单或销毁前情时取消旧计时回调和音频，避免旧实例在下一轮触发完成。

前情场景以六个真实 TextureRect 保存完整分镜，字幕和控件保留独立可编辑节点。用 AnimationPlayer 管各幕镜头，统一时钟管理暂停与销毁。代码引用现有静音设置，前情音频不复用当前仅在战斗状态播放的 `tone_player`。

## 实现顺序与验收

先用现有素材和简单剪影完成六幕可点击分镜，检查第一次看的玩家能否复述人物关系。同时制作中文老先生说书试音，选定音色后合成六幕旁白，再制作新增背景与道具，并按实际录音调整动作、镜头和阅读时间。本版最终验收包括中文旁白与字幕，原生和 Web 均需核对。

| 验收项目 | 完成标准 |
| --- | --- |
| 叙事理解 | 请三位事先未读故事的试玩者回答“找谁、带谁、为何离曹、为何受阻”；至少两位能独立回答四项。未达成时调整具体分镜或字幕 |
| 基本流程 | 主菜单进入前情，自动播完停在末幕，点启程进入教程；当前两段开场对白全程只出现于后备路径 |
| 跳过 | 在六幕中分别跳过，均只初始化一次教程，显示护送与寻兄目标 |
| 翻幕输入 | 检查鼠标快点、按住 Enter、鼠标与 Enter 同时操作，以及末幕启程，均不会多翻一幕或进入战斗动作 |
| 暂停与失焦 | 分别在转场、镜头推近和旁白中暂停，镜头与声音同步停止、同步续播 |
| 新旧存档 | 使用隔离临时存档验证已有存档与首次运行，文化卡重看前后通关和最佳分数一致 |
| 重试与返回 | 第一阵重试、Boss 重试按现有流程恢复；中途返回菜单后再次启程，前情从第一幕开始，旧回调失效 |
| 可读性 | 检查 960×540、默认 1280×720 与浏览器缩放，人物关系标签可对应角色，字幕无缺字或遮挡 |
| 中文说书 | 六幕声音一致，年龄感、断句和情绪符合老先生说书方向；全部人名地名读音清楚，导演说明与控制标记由听感检查确认 |
| 助手选声 | 每轮生成由助手查询并核对音色可用性；生成记录保存选定的 voice ID，同一版六幕与后续补录使用一致音色 |
| 本地凭据 | 文件中的 Key 用于生成；Shell 中放置不同 Key 时结果仍以文件为准，缺失或空字段在联网前提示；Git 忽略本地 `.env` |
| 音频成品 | 六幕均有独立音频和实际时长记录；字幕与所念内容相符，镜头节奏在总时长目标内；原生与 Web 导出使用工程内成品音频 |
| Web | 重新导出后在 Chrome 与 Safari 检查过场、静音、失焦和跳过；音频受阻时等待开启，或明确选择静音后显示完整字幕 |

## 第一关可随后改进的内容

前情完成后，建议先验证三处体验，再确定后续实现。

1. 闪避教学加入一名有清楚蓄力与出手的演示守军，让玩家通过躲过攻击理解 Space。
2. 在两波守军之间逐步介绍 K 格挡与 L 义气技能，让每次新提示对应即将遇到的场景。
3. 过关后加入关门开启、马车前行和“前往洛阳”的短演出，让护送任务在关卡首尾都有画面反馈。

这些改进作为后续建议，分别细化验收后再安排实现。
