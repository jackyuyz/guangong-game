# 战斗扩展：架刀弹反 · 偃月斩 · 道旁茶摊

更新：2026-11-16。状态：逻辑模块与无头测试已完成；尚未接入 `main.gd`，未经实机试玩。数值为调试起点。

## 1. 设计意图

原型战斗只有 J 连砍和空格闪避，最优解容易变成“贴脸狂按 J，见红条就闪”。扩展加入一对互相喂养的机制：

- **K 架刀 / 弹反**：读敌人前摇、在出手瞬间按 K，是一种比闪避更“关公”的正面应对。完美弹反奖励义气并制造破绽。
- **L 偃月斩**：义气攒满后的英雄一击。义气只能从*有效命中*和*完美弹反*中获得，所以它奖励的是打得好，而不是按得多。
- **E 道旁茶摊**（可选）：第二阵清空后、关前对话前的一次性歇脚点，给进入孔秀战前一个喘息与准备的节点。

六格血、检查点、单次命中、闪避无敌等原有规则不变。

## 2. 操作

| 按键 | 动作 | 条件 |
|---|---|---|
| K | 架刀 0.42 s。前 0.18 s 为**弹反窗口** | 不在挥刀（`attack_time`）或闪避中；冷却 0.65 s（从按下算）|
| L | **偃月斩**：消耗 4 义气，对前方 220 px（身后 30 px）内所有敌人造成 3 伤害 | 义气满 4；不在闪避中；冷却 0.9 s |
| E | 茶摊歇脚：回复 1 格血（上限 6），义气充满 | 第二阵已清空（phase 4、无敌人）；距茶摊 x=2060 不超过 85 px；每次行程一次 |
| J / Space / A D / Enter / Esc P / M | 保持原样 | — |

K、L 两键始终由模块消费（返回 true），哪怕当下无效（冷却、义气不足），以免误触别的操作。E 只在可歇脚时消费。J、Space 永不消费：若这次挥刀/闪避确实会发生，则顺带收刀（结束架刀）。

## 3. 行为与平衡

### 架刀与弹反
- 只防**正面**：受击方向与关羽朝向相反才生效（`facing * direction < 0`）。身后来的攻击照常受伤。
- **弹反**（按下后 ≤ 0.18 s 内被击中）：不掉血；义气 +2；立即清空 K 冷却（可连续弹反）；攻击者进入 `recover` 硬直（守军 1.25 s、孔秀 1.1 s，取消孔秀连招 `combo_pending`）；短暂顿帧与浅色火花，横幅“弹反！破绽已现”。
- **格挡**（窗口之后、架刀结束前被击中）：不掉血、不给义气、不打断对方；关羽后退 14 px。
- **孔秀横扫破防**：孔秀横扫（`move % 2 == 0`，即 HUD“! 横扫”）只能弹反或闪避。普通格挡会被打破（架刀结束、照常掉血），横幅提示“横扫破防 · 须精准弹反或闪避”。突刺可以普通格挡。这样闪避仍然是必要技能，横扫成为高风险高回报的弹反目标。
- 弹反时的攻击者识别：取正在 `strike`、`struck == true`、朝向与受击方向一致、离关羽最近的敌人。只改字典字段，不改动数组（`absorb_damage` 在主循环遍历敌人期间被调用）。
- 挥刀中、闪避中不能起架；开始挥刀或闪避会收刀。架刀时仍可移动；朝向随移动改变，因此背对敌人走路时不会防住。

### 义气与偃月斩
- 义气 0–4。每次有效 J 命中 +1（三段重斩同样 +1），完美弹反 +2，满值封顶。攒满时有一声提示音。
- 偃月斩是瞬发判定：按下当帧结算伤害，不复用主游戏的 `attack_time` / `swing_id`，避免普通挥刀判定重复命中。
- 范围内**没有敌人则不出招、不扣义气**（只有一声低音），避免空挥浪费。
- 出招：扣 4 义气；0.35 s 无敌（写入 `game.invincible`，取较大值）；震屏、顿帧、横幅“偃月斩！”。
- 伤害 3：守军（2 HP）必死；孔秀 16 HP 掉 3 并硬直 0.9 s。参考：攒 4 义气约需 4 次命中，等于把那 4 刀的价值翻倍，并附带群伤与无敌；整场孔秀战大约可放 1–3 次。
- 死亡敌人在遍历结束后用 `filter` 移除。若孔秀因此倒下，立即调用 `game._win()` 并返回，不再做后续处理（胜利优先）。

### 茶摊
- 位置 x = 2060，在第二阵守军区与关前对话触发点（x > 2170）之间。第二阵清空的第一帧横幅提示“道旁茶摊就在关前 · 走近按 E 歇脚”（只提示一次）。
- 效果：+1 血（不超过 6），义气充满。随后进入 Boss 时主游戏检查点照常把血量提到至少 4。

### 重置与检查点（设计决定）
- `reset()` 清除所有临时状态：架刀、冷却、义气、偃月斩、茶摊使用记录。
- **Boss 检查点保留义气**：进入孔秀战（`phase` 首次变为 6 且主游戏 `checkpoint` 非空）时，模块记录当时的义气 `checkpoint_resource`。Boss 重试后主游戏调用 `reset()`，下一次 `update()` 会把义气恢复为该快照。这与主游戏检查点恢复血量、时间、受击数的语义一致：第一次进 Boss 和重试时状态相同。
- 主游戏 `checkpoint` 为空时（新开局、从第一阵重新开始、返回菜单）快照自动作废。
- 从第一阵重试时茶摊可以再用一次（重试本身已回满 6 血）。

## 4. 接入步骤（由主程序负责）

```gdscript
const CombatExtensions = preload("res://scripts/combat_extensions.gd")
var ext = CombatExtensions.new()
```

1. `_start()`（或 `_reset_run()`）与 `_retry()` 中调用 `ext.reset()`。
2. `_update_play(dt)` 中每次调用一次 `ext.update(self, dt)`，建议放在计时器递减处。顿帧期间 `_update_play` 不运行，模块计时随之冻结；暂停、对白、死亡同理，模块内部也会检查 `state == "play"`。
3. `_unhandled_input` 中，在 `if state != "play": return` 之后、J/Space 处理之前：
   ```gdscript
   if ext.handle_key(self, key):
       return
   ```
   若偃月斩击杀孔秀，模块内部已调用 `_win()`，此时 `state` 不再是 `"play"`，主程序后续不会再结算。
4. `_hurt(direction)` 中，在现有 `invincible / 闪避 / state` 判断之后、`hp -= 1` 之前：
   ```gdscript
   if ext.absorb_damage(self, direction):
       return
   ```
5. 普通 J 命中、在 `enemy.hp -= ...` 之后、Boss 胜利判断之前：`ext.on_attack_hit(self, enemy, damage)`。
6. HUD 原生 Label 显示 `ext.status_text(self)`（≤ 约 35 个字符，例如 `K 格挡·弹反   L 偃月斩 义气 4/4 就绪   E 茶摊歇脚`）。底栏操作说明建议补上“K 架刀 L 偃月斩”。

### 可供表现层读取的公开状态
| 字段 / 方法 | 含义 | 建议表现 |
|---|---|---|
| `is_guarding()` / `guard_timer` | 架刀中 | 横刀姿势 |
| `in_parry_window()` / `guard_age` | 弹反窗口内 | 刀身微光 |
| `parry_flash` | 刚弹反（0.25 s）| 白色闪光 |
| `block_flash` | 刚格挡（0.2 s）| 金色火花 |
| `guard_broken` | 被横扫破防（0.4 s）| 踉跄 |
| `resource`, `RESOURCE_MAX`, `heavy_ready()` | 义气 | 4 颗义气珠 |
| `heavy_time` | 偃月斩姿势（0.35 s）| 大弧刀光 |
| `REST_X`, `rest_used`, `can_rest(game)` | 茶摊 | 在 x=2060 绘制茶摊；可歇脚时显示提示 |
| `parries`, `blocks` | 本次统计 | 结算可选显示 |

注意：茶摊目前**没有画面**，需由表现层在世界坐标 x = 2060 处放置道具。
