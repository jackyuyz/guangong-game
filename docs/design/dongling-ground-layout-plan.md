## 本机验证

218项相关隔离检查通过，其中23项新增道路集成检查覆盖相机、世界固定地标、脚底、茶摊、两波敌人、Boss引入／边界／失败重试及暂停。已检查编辑器2D真实节点、960×540原生教学／守军／茶摊／门前渲染，网页走过教学、第一阵到第二阵、失败重试与暂停，控制台无错误或警告。Boss为模拟状态原生渲染及逻辑回归，未真人完整通关。网页检查后仅将前景归入Ground，相关65项场景／道路检查复跑并重拍原生图、重导出；未重复网页该编辑器层级变更的专项操作。未公开发布。

## 当前问题的来源

- `dongling_pass.tscn` 的可走世界为3000逻辑像素，角色脚底默认在y=440；整幅原背景缩至约1210像素宽，包含远山、关门、斜向山路、岩石与近景拒马。它是一张带透视的完整场景图，不是三屏长的横向关卡切片。
- `level_view.gd` 每次随镜头把背景向右补偿镜头位移的92%，所以画面中的背景只相对屏幕移动约8%。角色横向走了很远，墙、石头和拒马仍近乎固定，无法代表同一套世界位置。
- 现有 `Ground/Fill`、三块纹理和y=442的直线已经把可走道路另铺了一层，但纹理是从原图截取并拉成横条；这种临时平台没有真正拆开原图中的近景障碍，也没有解决透视道路与水平脚底的关系。

## 推荐：保留素材，重新搭建横向道路

从后向前分成四层：

| 层 | 内容与移动规则 | 角色关系 |
| --- | --- | --- |
| 远景 | 山、天空、远树；允许低速视差 | 永远在人物后面，不参与碰撞 |
| 关口与墙段 | 关门只在Boss终点出现一次，墙、旗标和茶摊固定在世界坐标 | 随世界与镜头一致移动，不做“贴屏补偿” |
| 可行走道路 | 沿教学→守军→茶摊→Boss连续铺设，先保持现有横向玩法与脚底基线 | 主角、敌人、阴影和攻击范围共用道路坐标 |
| 前景 | 草、低石、拒马边缘，放在道路两侧 | 必要时遮住人物脚部；装饰不与行进路线争用位置 |

Godot的 [Parallax2D说明](https://docs.godotengine.org/en/stable/tutorials/2d/2d_parallax.html)支持各层独立设置相对镜头的移动速度；视差只能表达景深，不能代替可走道路与碰撞。

素材库已有 `environment/mountain-path.png`、`tree.png`、`rocks.png`、`wooden-barricade.png`，以及 `architecture/wall-section.png`、`dongling-gate.png`。优先使用这些原有独立素材组装；实际查看山路后确认它仍是斜向透视图，不能直接拉伸成3000像素水平地面。需要从现有纹理整理横向衔接段，或制作保留原画的派生分层图，不能把“有独立山路图”当作已经可无缝平铺。

## 障碍如何处理

- 真正挡路的实物放在可走路带外侧或关卡边界；若确实要挡住去路，要有单独碰撞和绕行／开放规则。
- 近景拒马若仅用于构图，就作为前景遮挡，不在角色脚底位置画成可踩的平台。
- 城门不铺成水平地面，不让角色走到墙面；Boss战区域止于门前，通关用演出表达放行。
- 先不引入跳跃或自由上下走位。把角色加上NavigationAgent也不会自动理解PNG中的石头；仍需要作者定义道路与障碍。

## 其他可行方向

| 方向 | 代价与适用情况 |
| --- | --- |
| 固定关口镜头，分波战斗 | 最适合保留整张概念背景；要调整教学、行进与茶摊流程，玩法会更像固定竞技场 |
| 沿透视山路行走的2.5D | 需要可走多边形、纵深缩放、前后遮挡排序，以及攻击距离／预警／相机重新校准，明显扩大玩法范围 |

本项目已有横版移动、两波守军、场景交互和Boss检查点，优先推荐分层横向道路。实施顺序应为：先搭出一小段无穿帮道路并检查人物比例与遮挡，再扩展全程，最后迁移旗标、训练靶、守军、茶摊、Boss和重试点并做整关验证。
